# Reproducible demonstration

Use the [README setup](../README.md#install-and-run), a clean Git checkout, and the running API/UI. Seed data is fictional; execution evidence below is generated by real assertions.

## Automated lifecycle

```bash
python3 scripts/demo.py --output .tools/demo-evidence.json
```

The script works through REST, never writes the database directly. It reopens PD-104 if necessary, moves it into progress, associates the predefined tests, links the running build's actual commit, executes the defective boundary case, runs corrected assertions, enters review, and resolves using fictional reviewer Lena Park (actor 5).

It stops on an unexpected pass/failure, HTTP error, dirty build, or failed resolution. Re-running adds a new truthful execution/history sequence rather than rewriting old evidence. It does not claim the controlled registry output is a CI run.

Recorded snapshot: [demo-evidence.json](demo-evidence.json). It was generated from clean build `33e1ea58395fe4448c065b3bbabc3d490a95eda5`; the record contains its actual commit, timestamps, binary fingerprint, one failing boundary execution, corrected passing executions, and resolved issue. This is a historical snapshot, not a claim that later commits were already tested at that timestamp.

## Interactive 90-second walkthrough

| Time | Screen/action | What to explain |
|---|---|---|
| 0–10s | Open overview | “These counts and the review queue come from SQLite through the API.” |
| 10–20s | Open PD-104 | “At subtotal $100 and 10% discount, expected total is $90. The defective fixture skips the threshold.” |
| 20–35s | Verification → Run defective fixture | “The same registered assertion actually runs and records Failed, with actual value $100.” |
| 35–45s | Show `DiscountCalculator.cs` beside `DefectiveDiscountFixture` | “The defect is `> 100`; the correction is `>= 100`. The defective snapshot is isolated so production remains correct.” |
| 45–60s | Link current build commit, run both corrected tests | “Every associated test must pass for this revision and linked commit; old evidence cannot close a changed issue.” |
| 60–70s | Open the actual [CI run](https://github.com/sarseej-shrestha/PatchDesk/actions/runs/38706832614) | “Backend, frontend, and real Chromium jobs passed. The browser job is separate from compilation.” |
| 70–90s | Move to InReview; choose Lena Park; enter note; resolve; view timeline | “This reviewer is simulated. The backend enforces the evidence rule, and the resolution is persisted without manual override.” |

Before recording an interactive demo, reset/seed the database so PD-104 starts in progress and unexecuted. If the scripted demo already resolved it, reopen and move to InProgress first. Add the fix reference **before** corrected executions, because linking code invalidates older evidence.

Useful command for inspecting the source change:

```bash
git show c841651:backend/PatchDesk.Api/Regression/DiscountCalculator.cs
```

That commit introduced both the isolated defective fixture and corrected production implementation. It does not pretend the production repository once shipped the defect; the bug is deliberately reproducible in a demonstration fixture.

For fresh CI evidence, open the latest completed run matching the commit you are demonstrating. Do not imply a historical CI run verified a newer commit.
